# Mock Interviews

用模擬口試檢查 fundamentals、研究答辯及追問表現。目前沒有已進行的 mock，不能由模板推定分數或弱點。

## Format

- 建議先以 20–30 分鐘混合 fundamentals / defense 練習，再依已知目標面試形式調整。
- 題目從 [Weakness Map](../WEAKNESS_MAP.md) 與 coverage 選擇，混合已測弱點、Strong 的變形與尚未測的領域。
- QA / SE 背景的 [Software Engineering](../topics/12-software-engineering.md) 在 mock / defense 中視同 Tier S；研究題串接 [Experimental Design](../topics/11-statistics-experimental-design.md) 與 [真實 portfolio evidence](../research-defense/portfolio-index.md)。有確認口試目標後才加入 [school-specific](../school-specific/README.md) 情境。
- 一次一題，先答再追問；若採面試模擬模式，短評後繼續，完整教學留在 session 結束後。
- 真實不會的回答照實記錄；必要推導 / code 不能由口述印象取代。

## Records

複製 [session template](session-template.md) 為實際的 `YYYY-MM-DD-mock-NN.md`。每次必須記錄 questions、my answers、follow-ups、score、weaknesses exposed、action items。

## After the mock

1. 用 [rubric](../diagnostic/scoring-rubric.md) 逐題評定，不以流暢表達掩蓋核心錯誤。
2. 把暴露的弱點連到題目證據，更新主表；不把整題評級套到未測子題。
3. Action item 要包含改善方法與驗證條件，排入 [review queue](../review/spaced-repetition.md)。
4. 更新 [Progress history](../PROGRESS.md)，保留 session 中的原始答案與後續修正。

Mock 不增加 30 題 Diagnostic 進度。一次良好表現不代表未測領域也已掌握。
